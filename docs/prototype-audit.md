# What carried over from the prototype

The baseline was the local 0.22.0 prototype, including its reviewed-save changes. Its 264 tests passed on November 22, 2026. The comparison below uses the running code and tests. The old description of a manual final Save covered only some write paths.

| Task in the prototype | Where to do it in Browser Recipes | Verification |
| --- | --- | --- |
| Choose an existing tab, run a read, keep working elsewhere | Open the toolbar runner. Choose the tab and recipe. The optional CLI uses the same dispatcher. | An installed extension read, navigated, wrote to a fixture and fetched a PDF while another tab stayed active. [Browser test](../integration/smoke.mjs) |
| Read an Outlook week under either Outlook hostname and compare it with Google | Select the calendar workflow from **Workflows**. Assign the source and destination, review the data for ChatGPT, then select missing blocks. | Isolated Chromium tested both calendar reads, the account guard, explicit import and the receipt on synthetic calendars. Another installed workflow compared news headlines without invoking inference. [Browser test](../integration/calendar.mjs) |
| Prepare a timed or all-day Google event and approve Save separately | Choose the corresponding single-event workflow. ## What still needs live verification

The current tests establish fixture behavior. No personal calendar event was imported during this audit. A real account still needs to complete OpenAI consent and inference, and the revised destination picker and Save recipes still need verification against a disposable Google calendar. The paired helper was exercised on Linux. Windows and macOS still need platform tests. The [local form examples](../examples/legacy-forms/) document widget-specific limitations.

Under **Allowed operations**, you can set the expected account identifier before running anything. If you leave it empty, the runtime learns the first unambiguous account it observes. The built-in recorder captures one top-level document per recording. It does not reconstruct a multi-page workflow from a demonstration. The Guide can explain the current step and suggest supported actions. Application writes still require the runner’s approval control.
